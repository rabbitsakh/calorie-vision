# RuStore: отказ «WebView / перенаправление на сайт»

## Что написал модератор (повторно)

> Приложение должно быть самоценным… Не приветствуем приложения, единственной целью которых является перенаправление на веб-сайт (WebView). Приложение может дублировать функциональность веб-сайта или обращаться к вебвью для выполнения некоторых задач, однако оно должно восприниматься пользователем как завершённый, самостоятельный продукт.

## Почему снова отклонили

Сборка **Capacitor с `server.url = https://calorievision.ru/...`** при старте сразу грузит сайт в WebView.  
Для модерации это почти то же, что TWA: «открыли приложение → открылся сайт».

## Что изменено (обязательно пересобрать APK)

1. **Убран `server.url`** — cold start только из assets APK (`rustore/cap-www/`).
2. Локальные экраны **без сети**: splash → welcome → демо-рацион (кольцо ккал, записи, таббар).
3. **Камера устройства** из оболочки (плагин / capture), превью локально.
4. Кнопка «Войти» опционально открывает продуктовую сессию для синхронизации — **после** самостоятельной оболочки, не вместо неё.

Сборка:

```bash
npm run rustore:cap:init
npm run rustore:cap:build
# → rustore/dist/app-release.apk
```

Перед загрузкой в Консоль: удалите старое приложение с телефона, поставьте новый APK, пройдите welcome **в авиарежиме** — экран дневника должен открыться.

## Проверка перед отправкой

- [ ] APK ставится с ярлыка «Calorie Vision»
- [ ] Авиарежим: welcome + демо-рацион открываются
- [ ] «Сфотографировать еду» открывает камеру / захват
- [ ] Нет адресной строки Chrome на старте
- [ ] Скрины витрины: welcome / рацион / камера / статистика (не лендинг)
- [ ] В описании нет формулировок «быстрый доступ к сайту»
- [ ] `versionCode` больше предыдущего в RuStore

## Не делать

- Снова включать `server.url` на cold start
- Заливать legacy Bubblewrap TWA
- Начинать приложение с маркетингового лендинга
