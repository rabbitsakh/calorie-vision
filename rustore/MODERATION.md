# RuStore: отказ «WebView / перенаправление на сайт»

## Что написал модератор

> Приложение должно быть самоценным… Не приветствуем приложения, единственной целью которых является перенаправление на веб-сайт (WebView).

## Почему так вышло

Текущий APK — **Bubblewrap TWA** (Chrome без UI вокруг `https://calorievision.ru`).  
Для модерации это часто = «обёртка сайта», особенно если:

- видны Custom Tabs / адресная строка (битые Digital Asset Links);
- первый экран похож на лендинг, а не на дневник;
- в APK нет нативных экранов / камеры / офлайн-оболочки.

TWA **не запрещён** сам по себе, но RuStore режет продукты, которые выглядят как «открыть сайт».

## План исправления (по приоритету)

### 1) Обязательно перед повторной подачей
1. Собрать **Capacitor Android APK** (`npm run rustore:cap:init` → `npm run rustore:cap:build`).
2. На телефоне: лаунчер → splash → сразу дневник/логин, **без** Chrome-бара.
3. Камера еды через системный интент (плагин), не «сайт в браузере».
4. Скриншоты витрины — только продуктовые экраны (дневник, фото, статистика), не лендинг.
5. В карточке: акцент на «приложение-дневник», сайт — зеркало / веб-версия.

### 2) Если снова отказ
- Локальный web-shell (кэш критичных экранов в APK) + API на сервер.
- RuStore Push SDK / FCM вместо чистого Web Push.
- Нативный onboarding (1–2 Activity) до WebView.

### 3) Не делать
- Повторно заливать тот же Bubblewrap TWA «как есть».
- В описании писать «удобный доступ к сайту» / «быстрый вход на calorievision.ru».

## Проверка перед отправкой

- [ ] APK ставится с ярлыка, имя «Calorie Vision»
- [ ] Нет адресной строки Chrome
- [ ] После входа — рацион / «+» / статистика
- [ ] Фото еды открывает камеру устройства
- [ ] Офлайн: черновик/очередь не теряется (как на вебе)
- [ ] `assetlinks` / App Links настроены при необходимости deep link
- [ ] Новый `versionCode` > предыдущего в RuStore
