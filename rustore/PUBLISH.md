## 1. Юрлицо и Консоль (один раз)

1. Зайти в [console.rustore.ru](https://console.rustore.ru).
2. Создать компанию (ООО / ИП / самозанятый — как требует форма).
3. Роль **Владелец** нужна, чтобы **добавить приложение**.
4. Загрузить версии могут Владелец / Админ / Релиз-менеджер / Разработчик.

## 2. Техника: TWA без Chrome-бара

Без Digital Asset Links модераторы и пользователи увидят **адресную строку Chrome** — часто режут или плохо смотрится.

### 2.1. Keystore (хранить вне git)

```bash
keytool -genkeypair -v \
  -keystore rustore/android.keystore \
  -alias calorievision \
  -keyalg RSA -keysize 2048 -validity 10000
```

Backup keystore + пароли — в сейф. Потеря = нельзя обновлять то же приложение.

### 2.2. Fingerprint на прод

```bash
keytool -list -v -keystore rustore/android.keystore -alias calorievision
# скопировать SHA256: AB:CD:...
```

На сервере / в `.env` продакшена:

```bash
TWA_SHA256_FINGERPRINTS="AB:CD:..."
```

Проверка после деплоя:

`https://calorievision.ru/.well-known/assetlinks.json`  
(должен отдавать JSON с `package_name`: `ru.calorievision.app` и вашим SHA-256).

### 2.3. Сборка (Windows: см. `WINDOWS.md`)

```bash
# JDK 17, ANDROID_HOME = корень Sdk
bash scripts/rustore-init.sh   # один раз
bash scripts/rustore-build.sh  # → rustore/dist/app-release.apk
```

### 2.4. Ручная проверка APK на телефоне

- [ ] Открывается без адресной строки  
- [ ] Логин (Google / VK / Telegram / email)  
- [ ] Фото → распознавание → сохранение  
- [ ] Офлайн-очередь / push (если доступны)

## 3. Создание приложения в Консоли

1. **Приложения → Добавить приложение** → имя `Calorie Vision`.
2. Тип: **Универсальный** (телефон; ТВ не нужны).
3. **Загрузить версию** → APK (проще для старта) или AAB (+ отдельно сертификат загрузки).
4. Дождаться обработки файла (черновик; обработанные файлы живут ~14 дней).
5. Заполнить карточку (тексты ниже / `listing.ru.md`).
6. Загрузить иконку и ≥3 скриншота.
7. Декларация данных / разрешения.
8. Отправить на **модерацию**.

Каждый следующий релиз: поднять `appVersionCode` в `twa-manifest.json`.

---

## 4. Требования к медиа (актуально)

### Иконка
- 512×512 px, PNG/JPG, ≤3 МБ  
- **без прозрачных краёв** — фон на всю площадь  
- готовый файл: `rustore/icon-512-store.png`

### Скриншоты телефона
- минимум **3**, рекомендуется 4–6 (до 10)  
- PNG/JPG, ≤3 МБ каждый  
- макс. 2160×3840; ориентир **9:16** (вертикаль), напр. **1080×1920**  
- реальный UI на русском, без чужих брендов крупным планом  
- первые **2** видны в выдаче — самые сильные кадры

Сценарии съёмки — в `listing.ru.md` и папка `rustore/screenshots/`.

## 5. Декларация данных (типично для нас)

Отметить по факту продукта (уточнить под вашу политику):

| Данные | Зачем |
|--------|--------|
| Email / идентификаторы аккаунта | вход |
| Фото еды (загрузки) | распознавание |
| Дневник питания, вес, вода | функциональность |
| Push-токен | напоминания (опционально) |
| Технические логи / аналитика | если включена Метрика |

Разрешения Android у TWA обычно минимальны (камера через WebView/Chrome). Не заявлять лишнего.

---

## 6. Частые отказы модерации

- Нет / битые asset links → видна адресная строка  
- Нет политики конфиденциальности  
- Скриншоты с чужими логотипами или не на русском  
- Обещания «похудеть / вылечить» без дисклеймера  
- Несовпадение package / подписи при обновлении  

---

## 7. После публикации

- Сохранить ссылку RuStore (для лендинга `/#install`)  
- Увеличить `appVersionCode` перед следующим билдом  
- По желанию: альфа-тестирование перед продом  
- Монетизация (RuStore Pay) — **отдельный этап**, не нужен для первой выкладки
